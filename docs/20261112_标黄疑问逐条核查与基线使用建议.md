# SeDPO 报告标黄疑问逐条核查

核查日期：2026 年 11 月 12 日。对象是用户已标黄的完整实验报告 Markdown，以及本地 CoopES 英文稿《Can Examples Synergize? Cooperative Example Selection for In-Context Learning》。本说明保留用户的标注，不覆盖原报告或重新生成 Word。报告与 Word 的内容已因用户新增标注而不再逐字一致。

## 一 当前判断

实验有价值。已有材料支持四组实验实际执行、各有 500 条唯一有效预测，Accuracy 与 F1 可以从逐题预测重算，模型、协议和文件也有溯源记录。但是，“已实际运行且分数可重算”与“已严格复现原稿比较条件”是两件事。

SeDPO 适合作为 CoopES 论文的一个方法基线。当前四行分数适合作为带设置说明的补充实验或外部参考；暂不宜直接混入同一受控比较的主表并重新标粗、据此宣称任一方法更优。若恢复了原 CoopES 运行的必要材料，可以只按原设置补评 SeDPO，无需仅仅为了形式再训练 CoopES。若无法恢复而需要新的公平主表，才需要在新协议下取得双方的结果；不能把只重跑 SeDPO 自动解释为双方已经对齐。

## 二 标黄问题逐条回应

### 1 未重跑 CoopES 及设置没有完全对齐

这不意味着 SeDPO 分数是假的，但直接影响比较结论。500 道题、50 个候选、模型名称和 4-shot 相同，只是粗粒度条件相同；具体题目、模型权重或量化、输入模板、解码及评分仍可能改变成绩。

并非所有新增基线都必须重跑已有方法：如果原方法的题目清单、模型、prompt、推理与评分设置能够恢复，新基线可以沿用这些条件，与已有结果比较。本项目的障碍是这些条件尚未被完整恢复，而不是“没有重新训练 CoopES”本身。

CoopES 第 IV-A 节写的是选择 50 个样本构成 training set、500 个样本构成 validation set。原稿没有说明这是否就是官方的 train/validation split，也没有把它明确界定为本次采用的 official test。此前把原表笼统称为“500 测试题”应收紧为“原稿汇报所用的 500 条评测样本，具体来源待核实”。此外还需明确 Shapley 效用计算、选择或调参、最终汇报分别使用哪些题，不能据文字缺失推定原方法发生泄漏，也不能默认已经严格隔离。

### 2 ARC-C 排除非四选项题并评测 500 题

固定四选项子集、在评测前确定筛选规则，并使用与预测正确率无关的固定哈希抽样，是可以公开说明的实验设计。采用 500 题本身不使结果失去研究价值，也不要求为了“规范”一定使用全部 1172 题。

限制在于：本次结果应称为“ARC-C 四选项官方测试子集 500 题”，不能称为“ARC-C 全官方测试集成绩”。若要与原表作受控比较，还需匹配原表评测题目；同样是 500 题也可能难度不同。CoopES 稿件的 500 条 validation 描述不足以恢复那份清单。本次是探索性实验，原测试来源此前已用于诊断；不能把固定哈希抽样描述成完全未接触测试的预注册实验。

### 3 OpenBookQA 提供 fact1

本项需要纠正上一版报告的表述。CoopES 原稿第 6 页附录 A 的 Table IV 明确给出带 {fact} 的 OpenBookQA 模板，其形式是 Knowing that 后接 fact、再提出 question。因此，原稿在设计层面使用事实信息这一点是已知的，而不是完全未知。

提供数据集关联事实，并不等于把 answerKey 交给模型。在规定为提供该事实的任务设置下，这是合理输入，虽然事实可能明显帮助答题。它会使任务不同于不提供事实的设置，所以应对所有被比较方法一致处理。

仍未核实的是：原实际运行是否遵循稿件、{fact} 是否对应同一 fact1 字段、是否所有示例及目标均包含事实、怎样拼接选项和答案。当前统一对话输入也与原稿 Table IV 的简写模板不完全相同。不能继续用“原稿可能根本不用 fact”解释 SeDPO 的较高分，也不能仅凭出现 {fact} 就断言两次运行已完全一致。

### 4 训练内部 ID 与最终官方 ID 不同

这是编号体系的区别，本身不是数据错误。训练文件可用池内索引，最终冻结协议保留官方字符串 ID；关键是索引能否指回正确的题目内容和答案。

此次又检查了报告训练例子的 query 内部 ID=21、候选 ID=973 和 146：按题干与有序选项匹配，三条在对应训练池中各找到唯一内容匹配，答案一致。因此，这个例子没有发现编号造成的内容或标签错配。此项只覆盖所核对的例子；较广的池与测试重叠等审计见既有 data_review.json，不以三条检查冒充全量数据重新审计。

不要把内部 ID=21 直接解释成某个最终测试官方 ID，也不要把不同 split 的数字 ID 相同当作同一题。应通过官方 ID 的映射或题干及选项内容验证。

### 5 Llama OpenBookQA 的 89.60 及较原表高 14.40 个百分点

当前结果是 448/500，Accuracy=89.60%；从相同逐题结果计算 Weighted-F1=89.6105857860%。用户给出的 CoopES 表值为 75.20% 和 75.3462%，所以算术差值分别为 +14.40 和 +14.2644 个百分点。差值计算没有问题，但它是两个实验数值的差，尚不是方法净效应。

较大的差距值得优先核查，而不是自动认定造假、也不是自动认定 SeDPO 有 14.4 个百分点的算法优势。优先检查评测 split、原模型制品、完整 prompt、选项与字母评分方式、事实拼接、样本 ID，以及原表是否存在录入错误。原稿给出的模型脚注指向 Ollama；本次采用 Transformers 加载本地 FP16 权重。执行制品尚未证实一致，不能自行断定原稿一定使用了某种量化规格。

当前四组 Accuracy 分别是 OBQA Llama 89.60%、OBQA Qwen 90.40%、ARC-C Llama 82.80%、ARC-C Qwen 88.40%。它们不支持把这次实验写成“证明 CoopES 全面优于 SeDPO”。保留真实分数，先澄清比较条件。

## 四 对流程规范性的具体评价

目前有价值的规范措施包括：保留真实预测与失败产物；检查最终 500 个唯一 ID；隔离最终 query 与答案文件；从 train 构成推理候选池；保留配置、权重与结果哈希；单独记录内部验证；遇到无效数值停止而非填 A；不按目标排名改分。这些为复核实际运行提供了依据。

当前尚不能支撑严格主表比较的部分包括：SeDPO 与原方法评测样本角色及 ID 未确认一致；模型与 prompt/解码尚未完整匹配；测试来源已用于诊断；只有一个训练种子；SeDPO 的 300 源 query 和全训练候选构造预算与原方法的“50 training”角色没有完整对照解释。

不同方法可以有自己的训练损失、学习率、warmup 和必要训练数据。公平比较不要求所有方法训练超参数完全相同，但应说明学习型检索器额外使用的数据与离线计算成本，并让最终任务输入、reader、测试集合和计分方式一致。缩短 warmup 的合理修复、内部验证选模型、单个种子或使用 500 题均不自动使实验无效；它们分别影响实现定位、选模说明、结论稳定性和适用范围。

## 五 加入论文前的最小闭环

1. 优先从原 CoopES 实验材料恢复 50 候选与 500 评测样本的 ID、官方 split，以及效用计算/调参/汇报各自的数据角色。
2. 恢复 reader 的精确模型制品与推理配置、完整实际 prompt、事实使用、答案解析及 Weighted-F1 计算方式。
3. 对照本次 SeDPO：若相同，保存证据；若不同，仅按需要重新运行 SeDPO 的检索或 reader 评测，先不默认重训四套检索器。只有训练数据隔离或方法实现本身有问题，才讨论重训。
4. 核对一批原始题目、答案、示例与输出的端到端映射，并尽可能取得原方法逐题预测，避免只比较聚合分数。
5. 按实际重复实验情况报告稳定性；条件不齐时保留为单独、带限制说明的补充实验，不当作已经对齐的主表排名。

本次核查没有重跑实验、改变参数、覆盖用户标注或修改现有分数。原报告关于 fact 的不准确表述由本说明更正；如需更新正文与 Word，应在保留用户批注后另存修订版。
